# Breadth B1, Steps 2–3 — Cranfield asset pack and evaluation (mock) — report

## How to run it on another laptop
The Cranfield data is not in git (third-party, BSD; the papers are publisher copyright). Once:
1. Free MathWorks account → download https://www.mathworks.com/matlabcentral/fileexchange/50938
   (`cvatutor-1.1.0.zip`, 16.2 MB) → `data/reference/cranfield/cvatutor-1.1.0.zip`
   (the converter checks its sha256).
2. `.venv/bin/python -m pip install scipy`
3. `env -u PYTHONPATH .venv/bin/python -m data.cranfield.convert` → 16 episodes in
   `data/episodes_cranfield_dev/` (6) and `data/episodes_cranfield/` (10).
4. Run (mock; add `--backend llamaserver` and the lane settings for the board, as for the boiler):
   ```
   env -u PYTHONPATH .venv/bin/python run_demo.py --backend mock --arch multi \
       --overlay configs/v3.yaml,configs/cranfield.yaml --all \
       --episodes-dir data/episodes_cranfield_dev --tag dev --out results/cranfield_dev
   ```
   `--arch single --overlay configs/cranfield.yaml` for the single agent. Tests:
   `.venv/bin/python -m pytest tests/test_cranfield_pack.py tests/test_cranfield_data.py`.
`configs/cranfield.yaml` and `fingerprint.json` are committed; regenerate them only with
`python -m data.cranfield.fingerprint` then `python -m data.cranfield.calibrate`.

## Decisions taken (by me, recorded)
1. **Frozen-instrument rule, changed on dev.** First version: stuck tolerance = 0.5 × the smallest
   healthy 3-min MAD (fitted). On dev set 6.1 the water-density meter, varying normally (86
   distinct values, MAD 1.8e-4 vs tolerance 5.2e-4), read as frozen on every tick, so every
   pre-fault tick alarmed (false-alarm rate 1.0). Now: frozen = exactly constant over 3 min
   (tolerance 1e-12), DERIVED from the meaning of the check; off for the three tags that are exactly
   constant on healthy data (FT407 flow and temperature, PT417). Decided on a dev episode (allowed);
   it removes a fitted factor rather than adding one. Result on 6.1: false alarms 1.0 → 0.042.
2. **Sides** `supply` (air and water inlet lines, pump) / `process` (riser and separators), from the
   flow path; faults 1–2 act on supply, 3–6 on process.
3. **Band wildcard** `"*"` in case signatures: direction derived, speed band not derivable. Matches
   the same (tag, direction) at any band (`CaseLibrary.resolve_wildcards`). Boiler cases never use it.
4. **T7 detection metric** (new; no earlier result uses it): detection rate inside the fault windows,
   false-alarm rate outside them split into BEFORE the fault (the literature's definition) and AFTER
   it (recovery transients, labelled normal by the source), detection delay. Ticks dated at
   publication, (k+1)·tick.
5. `--overlay` accepts a comma-separated list (`configs/v3.yaml,configs/cranfield.yaml`); a single
   path behaves as before.

## Why the false alarms (measured on dev, not tuned)
- **PT417** (2" line pressure: isolated, uncontrolled) sits at a different level each test day; its
  normal-set spread is tiny, so another day's level trips its limit or rate (dev 2.2, 3.2, 5.1).
- **Operating regimes outside the normal runs**: the slugging sets run at lower air flow and higher
  top-separator level than any normal run, before the fault starts (dev 5.1: `ft305 lo`,
  `vc302 lo`, `li405 hi`).
- **Recovery after the fault** (labelled normal by the source) accounts for most of the remaining
  "false" alarms on 1.2, 2.2, 4.2 (before-fault rate 0.0, 0.0, 0.21; after 0.83, 0.79, 0.60).
Thresholds fitted on three normal runs do not transfer across test days of a real rig. No threshold
was changed in response (the rules forbid tuning on fault episodes).

## Disagreements recorded, not resolved
1. **Pre-registered signatures CF-3 and CF-4 are not confirmed by belief** (belief top-1 ≈ 0 on
   3.3, 4.1, 4.3). Either the derived directions are wrong (e.g. the ASSUMED PT312 position, or
   back-pressure not reaching the supply because the flow controllers act faster than the 10-min
   slope), or the 10-min slope signature does not see them. Not revised: the library is
   pre-registered; any revision is a new, separately committed library tested on dev only.
2. **Slugging (CF-5) cannot be written as a signature**: its defining feature is oscillation, which
   a (tag, direction, band) triple of a 10-min slope does not represent. A limitation of the
   signature vocabulary, worth stating in the paper.
3. The evaluator's `Q2_heldout_cases_without_episodes` lists the boiler's held-out cases on
   Cranfield summaries (cosmetic; `_q2_split` is boiler-only). Not fixed.
